= Roadmap
:description: The phases of the rebuild, in order, with what each delivers and when it is done.

The rebuild runs on the branch `epic/rebuild`. The phases are strictly serial:
each is completed before the next starts. `main` receives the rebuild only as a
whole.

[cols="1,4,3,1",options="header"]
|===
|Phase |Content |Done when |Status

|0 Foundations
|`mise.toml`; Maven modules `core`, `cli`, `server`; legacy removed (Maven
wrapper, native Dockerfiles, old sources); Antora with the ITBH theme and
Diátaxis; licence Apache-2.0 with SPDX headers
|Build and docs build succeed
|done

|1 Rendering core
|Current openhtmltopdf and PDFBox; in-memory rendering; JSON data; Qute strict
and without reflection; resolver for assets and attachments, with an interface
for external URLs (implemented with the host allowlist in phase 3); image
limits; SVG in secure mode; caches; PDF 1.7; veraPDF; CLI `render` with
`--attach`; CLI distribution with generated `NOTICE`, licence texts and licence
check; Spotless formatting; JMH benchmark
|The demo template renders to PDF/UA confirmed by veraPDF
|done

|1a Proof of concept
|Demo template with all building blocks, rendered to PDF, XHTML, email HTML,
plain text, DOCX and ODT; document model with accessibility checker; DOCX and
ODT writers without an office library; running headers and footers with page
numbers from `@page`; decorative images as PDF artifacts; CLI formats and
`verify`; `mise run check-formats` with veraPDF, axe-core, ODF validator and
LibreOffice
|Every format passes its checks — otherwise the set of building blocks is
reduced before anything builds on it
|done

|2 Schema and validation
|Schema derivation from the syntax tree; field definitions; field type
`image`; formatting functions for date, number and currency, per language;
language variants (`template.<lang>.xhtml`) with RFC 4647 selection and one
shared schema; CLI `validate`, `schema`, `check`, `--lang`; errors with JSON
Pointer
|The test corpus yields correct schemas and precise error locations
|done

|3 Server
|PostgreSQL with Flyway; revisions; HTTPS fetcher with host allowlist; assets
stored once per hash and served at
`+/assets/{sha256}+`; publish checks; REST API; problem details with URNs;
worker pool with 503; warm-up before readiness; `Accept-Language` and
`lang` parameter, `Content-Language`, `Vary: Accept-Language`; formats per
template (406)
|Create, publish, validate and render work through the API
|done

|4 Layouts
|`+{#insert}+` areas; style catalog; components as user tags with
`component.json`; whitelist check; free CSS fallback; `.dotx`, `.ott` and
`email.css` per layout; message files per language for layout texts; fonts
shared by many templates held in memory once per hash
|A layout change never alters a published template unnoticed
|

|5 Operations
|Containerfile with mise, JRE and AOT cache; generated `NOTICE` and licence
texts in the image; Helm chart for Kubernetes and
`podman kube play`; `kubeconform`; CI smoke test; load test
|Several pods render under load and the autoscaler reacts
|

|6 Formats complete
|Writers complete: `.dotx`/`.ott` per layout as base of styles, headers and
footers; image sizes from the template; SVG with PNG fallback; `rowspan`;
`multipart/alternative`; email HTML written through the StAX writer
instead of string assembly
|Every format passes its automated checks; DOCX also passes Word's
accessibility checker
|

|7 Editor, stage 1
|Qute pages with htmx: management, field definitions, example data,
publishing; CodeMirror 6 with Qute mode, completion and server diagnostics; PDF
preview; ETag conflict detection; editing language variants side by side
|An experienced editor publishes a template without a developer
|

|Prototype
|Clickable block editor, tested with real editors
|The interaction design is settled
|

|8 Editor, stage 2
|TipTap block editor; Qute only as placeholder, loop and condition nodes; own
JSON format with translation to Qute XHTML in `core`; one-way switch to code
mode
|An editor without Qute knowledge creates an accessible template
|

|Later
|Authentication and authorization: OIDC with roles, an OIDC provider
(Keycloak) in the chart for podman; until then the API is open. QR code and
chart components; real-time collaboration
|–
|
|===
