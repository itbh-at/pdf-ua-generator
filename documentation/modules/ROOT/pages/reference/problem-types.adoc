= Problem types
:description: The problem type URNs the REST API returns, with status code and meaning.

All errors of the REST API are RFC 9457 problem details with the media type
`application/problem+json`. The `type` member identifies the kind of error.
Project-specific types are URNs of the form
`urn:itbh:pdf-ua-generator:problem:<name>`. A URN is used only after it is
listed on this page.

Validation errors carry an `errors` member with one entry per violation:

[source,json]
----
{
  "type": "urn:itbh:pdf-ua-generator:problem:invalid-data",
  "status": 422,
  "title": "Invalid data",
  "detail": "2 problems; see errors",
  "instance": "/templates/invoice/validate",
  "errors": [
    { "detail": "must be a number", "pointer": "#/items/2/price" },
    { "detail": "is required", "pointer": "#/customer/name" }
  ]
}
----

Every problem found is one entry of `errors`. `pointer` is a JSON Pointer to
the offending value in the request data, written as a URI fragment; `location`
names a place in the document template or layout instead
(`template.xhtml, line 12, column 5`, or `template.json#/fields/total` in the
descriptor). When the entries have
different types, as for `publish-rejected`, each carries its own `type`.

== Types

[cols="2,1,4",options="header"]
|===
|Type |Status |Meaning

|`urn:itbh:pdf-ua-generator:problem:invalid-data`
|422, 400
|The data does not match the JSON Schema of the revision of the document
template; `errors` lists every violation (422). 400 if the data is not a JSON
object at all.

|`urn:itbh:pdf-ua-generator:problem:format-not-supported`
|406
|The requested output format is not offered by the document template (its
descriptor lists `formats`), or none of the media types in `Accept` is an output
format.

|`urn:itbh:pdf-ua-generator:problem:template-error`
|422
|The document template or layout cannot be parsed or rendered: a Qute syntax
error, a value it uses but the data lacks, or rendered output that is not
well-formed XHTML.

|`urn:itbh:pdf-ua-generator:problem:accessibility`
|422
|The rendered document violates an accessibility rule: no title or language,
a skipped heading level, an empty heading, an informative image without alt
text, a table without header cells, or a link without text. See
xref:reference/building-blocks.adoc#_accessibility_rules[Accessibility rules].

|`urn:itbh:pdf-ua-generator:problem:resource-rejected`
|422
|A resource the document template or layout references is not allowed or not
available: a forbidden URI scheme (`file:`, `http:`, `data:`, …), a path outside
the document template or layout, a missing file, an external URL outside the host allowlist, or a
resource above the size limit.

|`urn:itbh:pdf-ua-generator:problem:image-rejected`
|422
|An image is not PNG, JPEG or SVG, exceeds the size or dimension limits, or
comes from a host that is not allowed.

|`urn:itbh:pdf-ua-generator:problem:attachment-missing`
|422
|The data refers to a request attachment that was not sent.

|`urn:itbh:pdf-ua-generator:problem:publish-rejected`
|422
|A revision failed the publish checks. `errors` lists every problem with its
own type: errors in the document template or layout, invalid example data,
accessibility violations.

|`urn:itbh:pdf-ua-generator:problem:not-found`
|404
|The document template or layout, the revision or the asset does not exist, or
the document template or layout has no published revision yet.

|`urn:itbh:pdf-ua-generator:problem:conflict`
|409
|The request contradicts the state of a revision: publishing a revision that
is already published, or deleting a published revision.

|`urn:itbh:pdf-ua-generator:problem:invalid-bundle`
|400
|The uploaded archive is not a ZIP file, contains a path that leaves the
bundle or occurs twice, exceeds the size or file limits, or lacks
`template.xhtml`.

|`urn:itbh:pdf-ua-generator:problem:invalid-request`
|400
|The request itself is malformed: an invalid id of a document template or
layout, a malformed `lang` parameter, or a multipart render request without a `data` part.

|`urn:itbh:pdf-ua-generator:problem:overloaded`
|503
|Every rendering thread is busy and the queue is full. The response carries
`Retry-After`; retry after that many seconds.
|===
