= Publish and render a template through the API
:description: Upload the demo template, publish it, validate data and render documents with curl.

Prerequisites: a running `podman` — on Linux its user socket
(`systemctl --user enable --now podman.socket`), on macOS a started machine
(`podman machine start`) — and the toolchain from `mise install`. mise picks
the right socket for either system; an explicit `DOCKER_HOST` in the
environment overrides it.

. Start the service in dev mode; it starts PostgreSQL in a container:
+
----
mise run dev
----

. Pack the layout as a bundle. The demo content pins `demo-layout@1`, so the
layout is published first. A bundle carries the layout's files plus an
`example.json` for the publish checks:
+
----
mkdir -p /tmp/layout
cp -r demo/layout/. /tmp/layout/
printf '{}' > /tmp/layout/example.json
(cd /tmp/layout && zip -r ../layout.zip .)
----

. Upload and publish the layout as revision 1 of `demo-layout`:
+
----
curl -X POST -H 'Content-Type: application/zip' --data-binary @/tmp/layout.zip \
  http://localhost:8080/templates/demo-layout/revisions
curl -X POST http://localhost:8080/templates/demo-layout/revisions/1/publish
----

. Pack the demo content as a bundle. The fonts, styles and images live in the
layout, so the content bundle holds only the template, its language variants,
the descriptor, and the example data and attachment:
+
----
mkdir -p /tmp/demo/example
cp demo/demo.xhtml /tmp/demo/template.xhtml
cp demo/demo.de.xhtml /tmp/demo/template.de.xhtml
cp demo/demo.json /tmp/demo/template.json
cp demo/data.json /tmp/demo/example.json
cp demo/photo.png /tmp/demo/example/
(cd /tmp/demo && zip -r ../demo.zip .)
----

. Upload it as the first revision of the template `demo`:
+
----
curl -X POST -H 'Content-Type: application/zip' --data-binary @/tmp/demo.zip \
  http://localhost:8080/templates/demo/revisions
----

. Publish revision 1:
+
----
curl -X POST http://localhost:8080/templates/demo/revisions/1/publish
----

. Validate data:
+
----
curl -H 'Content-Type: application/json' -d @demo/data.json \
  http://localhost:8080/templates/demo/validate
----

. Render a PDF with the photo as attachment:
+
----
curl -F data=@demo/data.json -F photo=@demo/photo.png -H 'Accept: application/pdf' \
  -o demo.pdf http://localhost:8080/templates/demo/render
----

. Render other formats with `format`, and email HTML without attachments:
+
----
curl -H 'Content-Type: application/json' -d @demo/data-email.json \
  'http://localhost:8080/templates/demo/render?format=email-html' -o demo.html
----

. Render the German variant with `Accept-Language` (or `?lang=de`); the response
carries `Content-Language: de`:
+
----
curl -F data=@demo/data.json -F photo=@demo/photo.png -H 'Accept: application/pdf' \
  -H 'Accept-Language: de' -o demo.de.pdf http://localhost:8080/templates/demo/render
----

. Get plain text and email HTML in one response with `Accept: multipart/alternative`
(text first, HTML last); the service builds the body and never sends mail:
+
----
curl -H 'Content-Type: application/json' -d @demo/data-email.json \
  -H 'Accept: multipart/alternative' -o demo.eml http://localhost:8080/templates/demo/render
----
