= Upload and render a document template through the API
:description: Upload the demo document template (validated and released on upload), validate data and render documents with curl.

Prerequisites: a running `podman` — on Linux its user socket
(`systemctl --user enable --now podman.socket`), on macOS a started machine
(`podman machine start`) — and the toolchain from `mise install`. mise picks
the right socket for either system; an explicit `DOCKER_HOST` in the
environment overrides it.

. Start the service in dev mode; it starts PostgreSQL in a container:
+
----
mise run dev
----

. Pack the layout as a bundle. The demo document template pins `demo-layout@1`,
so the layout is uploaded first. A layout carries only styles, so its directory is a
complete bundle as it is (no example data):
+
----
(cd demo/layout && zip -r /tmp/layout.zip .)
----

. Upload the layout as revision 1 of `demo-layout`. It is validated and
released for use in one step:
+
----
curl -X POST -H 'Content-Type: application/zip' --data-binary @/tmp/layout.zip \
  http://localhost:8080/templates/demo-layout/revisions
----

. Pack the demo document template as a bundle. Every demo is a self-contained
bundle directory, so packing is just zipping it. The bundle of the document
template (`demo/content/`) holds the default variant, the other language
variants, the descriptor, and the example data and attachment; the fonts, styles and images live in the
layout. (`data-email.json` is only a render input for the format check, not
part of the bundle.)
+
----
(cd demo/content && zip -r /tmp/demo.zip . -x data-email.json)
----

. Upload it as the first revision of the document template `demo`; it is
checked with its `example.json` and released:
+
----
curl -X POST -H 'Content-Type: application/zip' --data-binary @/tmp/demo.zip \
  http://localhost:8080/templates/demo/revisions
----

. Validate data:
+
----
curl -H 'Content-Type: application/json' -d @demo/content/example.json \
  http://localhost:8080/templates/demo/validate
----

. Render a PDF with the photo as attachment:
+
----
curl -F data=@demo/content/example.json -F photo=@demo/content/example/photo.png -H 'Accept: application/pdf' \
  -o demo.pdf http://localhost:8080/templates/demo/render
----

. Render other formats with `format`, and email HTML without attachments:
+
----
curl -H 'Content-Type: application/json' -d @demo/content/data-email.json \
  'http://localhost:8080/templates/demo/render?format=email-html' -o demo.html
----

. Render the German language variant with `Accept-Language` (or `?lang=de`);
the response carries `Content-Language: de`:
+
----
curl -F data=@demo/content/example.json -F photo=@demo/content/example/photo.png -H 'Accept: application/pdf' \
  -H 'Accept-Language: de' -o demo.de.pdf http://localhost:8080/templates/demo/render
----

. Get plain text and email HTML in one response with `Accept: multipart/alternative`
(text first, HTML last); the service builds the body and never sends mail:
+
----
curl -H 'Content-Type: application/json' -d @demo/content/data-email.json \
  -H 'Accept: multipart/alternative' -o demo.eml http://localhost:8080/templates/demo/render
----
